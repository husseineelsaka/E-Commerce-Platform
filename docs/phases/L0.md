# L0 — S25

## Goal

Establish the eight-module build, local infrastructure, Config Server, Eureka, and skeleton applications.

## Decisions

**DECISION:** Use a native Config Server backed by `config-repo/`.
**OPTIONS CONSIDERED:** Native files; Git-backed config.
**REASON:** The L0 repository is local and must start without another service.
**TRADE-OFF:** The default path assumes Maven starts Config Server from its module directory.
**WHAT WOULD MAKE US REVISIT:** A remote deployment needing separately versioned config.

**DECISION:** Keep the three architecture drawings as SVG files in `docs/architecture/` instead of photographed paper drawings.
**OPTIONS CONSIDERED:** Photographed paper drawings (handbook §10.3); SVG drawings in the repository.
**REASON:** SVG drawings can be reviewed in a PR diff and updated whenever the ADD changes; a photo cannot.
**TRADE-OFF:** This departs from the handbook's "photographed paper drawings" wording, so the trainer may ask for paper versions.
**WHAT WOULD MAKE US REVISIT:** The trainer requiring paper drawings at a gate.

## Startup commands

```sh
cp deployment/docker/.env.example deployment/docker/.env
docker compose -f deployment/docker/docker-compose.yml --env-file deployment/docker/.env up -d
mvn -pl platform/config-server spring-boot:run
mvn -pl platform/eureka-server spring-boot:run
bash scripts/verify-l0.sh
```

Use separate terminals for the two long-running Maven commands and replace the example values in `.env`.

## Tests

`mvn -B verify` builds the reactor; `bash scripts/verify-l0.sh` checks eight container health states, both application health endpoints, Config Server's application response, and Eureka registration.
